## [1.0.0] - 2026-10-22

### Added
- **Phase 1: Repository Foundation** — Repository structure, governance files (AGENTS.md, CONTRIBUTING.md, CODE_OF_CONDUCT.md, SECURITY.md), pre-commit hooks, Makefile skeleton, ADR template
- **Phase 2: Core Stack** — Docker Compose stack with Traefik v3.4, n8n (queue mode), PostgreSQL 16, Redis 7, Qdrant v1.19.2; Traefik static/dynamic config with security headers, rate limiting, basic auth; PostgreSQL init scripts with ops schema and ops_writer role
- **Phase 3: Security Hardening** — Secrets generator script, network segmentation (edge/app/data), Docker socket proxy (tecnativa/docker-socket-proxy), Traefik middlewares (security headers, rate limiting, auth), container hardening (no-new-privileges, cap_drop: ALL, read_only), n8n hardening (telemetry off, execution pruning, node exclusions)
- **Phase 4: Queue Mode & Scaling** — n8n split into main, webhook processor, and scalable workers (WORKER_REPLICAS); EXECUTIONS_MODE=queue with Redis Bull queue; Traefik routing (UI to main, /webhook* to webhook); healthchecks per role; Makefile scale/workers targets; benchmark workflow; ADR 0002
- **Phase 5: Backup & Restore** — Backup service (Alpine-based, pg_dump, Qdrant snapshots, age encryption, restic/S3 sync, cron); retention policies (daily 7, weekly 4, monthly 6); restore.sh, restore-test.sh; make backup/restore/restore-test; docs/backup-restore.md runbook; ADR 0003 (restic vs rclone)
- **Phase 6: Error Handling** — ops.dead_letters table, ops.alert_dedupe, global_error_handler workflow (Error Trigger → DLQ → Telegram alert with dedupe), retry_with_backoff sub-workflow (exponential backoff + jitter, retryable 429/5xx, Retry-After), dlq_replay workflow (list/replay/discard with auth), healthcheck_ping; bootstrap service; chaos demo workflow; ADR 0004, 0005
- **Phase 7: LLM Cost Tracking** — ops.model_pricing (with valid_from/valid_to for price changes), ops.llm_usage ledger, fn_compute_llm_cost() function + trigger, views (daily/by-workflow/MTD); log_llm_usage (normalizes OpenAI/Anthropic/Gemini), budget_guard (hourly, 80%/100% alerts, optional enforcement), llm_cost_report (weekly Telegram); docs/llm-cost-tracking.md; SQL unit tests
- **Phase 8: Human-in-the-Loop** — ops.approvals table, ops.approval_events audit, ops.approval_policies; request_approval workflow (Telegram inline buttons, signed callback token, escalation to secondary, double-click protection); needs_approval helper; policy.json; docs/human-in-the-loop.md with state diagram; ADR 0006, 0007, 0008
- **Phase 9: Showcase Demo** — showcase_ai_ops workflow (triage with RAG, LLM classification, approval gate, cost logging, outbox); mock LLM service (deterministic, injects failures); seed-qdrant-demo.sh; scripts/demo.sh; make demo; docs/demo.md with Mermaid sequence diagram
- **Phase 10: Observability** — scripts/doctor.sh (comprehensive health checks with colored output, --json); compose.monitoring.yaml (Uptime Kuma, Prometheus, Grafana with provisioned dashboard); Makefile additions (restart, logs SERVICE=, ps, upgrade, rollback, env-check, clean); scripts/env-check.sh; docs/operations.md
- **Phase 11: CI/CD** — .github/workflows/ci.yml (lint, n8n workflows validation, smoke test, restore drill, SQL tests); .github/workflows/security.yml (gitleaks, Trivy FS/config/image, dependency review); .github/workflows/release.yml (release-please, multi-arch backup image to GHCR with SBOM, release archive); .github/dependabot.yml; docs/contributing-ci.md
- **Phase 12: Testing** — tests/smoke/smoke.sh; tests/integration/ (pytest with fixtures for n8n, webhook, DB); tests/sql/test_llm_cost.sql (12 test cases); tests/restore/restore_test.sh; tests/conftest.py, tests/utils.py; docs/testing.md
- **Phase 13: Documentation** — docs/architecture.md (C4 diagrams, network matrix, data flows, failure modes); docs/deployment.md (sizing, DNS, UFW, deploy, upgrade, backup keys); docs/faq.md, docs/troubleshooting.md; ADRs 0004-0008; docs/assets/logo.svg, social-preview spec, screenshot/demo GIF instructions; docs/github-setup.md
- **Phase 14: Release Polish** — Security hardening (cap_drop: ALL, read_only: true, non-root users); workflow UUIDs; CHANGELOG v1.0.0; release workflow verification

### Security
- No secrets in repository history (gitleaks verified)
- All secrets via .env (gitignored), generated by scripts/generate-secrets.sh
- Age encryption for backups (private key offline)
- Docker socket proxy for Traefik (least privilege)
- Container hardening: cap_drop: ALL, read_only: true, no-new-privileges, non-root users
- Traefik: exposedByDefault=false, security headers, basic auth on dashboard
- Qdrant API key required, internal network only by default
- n8n: telemetry off, execution pruning, dangerous nodes excluded

### Changed
- Workflow top-level IDs now stable UUIDs (16 workflows)
- Compose files: added cap_drop: [ALL], read_only: true, explicit user directives
- Fixed JSON escape sequences in workflow files (request_approval.json)
- CHANGELOG updated with full history

### Fixed
- JSON escape sequences in workflow files (\` sequences in functionCode)
- llm_cost_report.json missing comma after connections object
- compose.yaml and compose.prod.yaml security hardening
